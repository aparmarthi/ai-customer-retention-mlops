## Dataset / Label

- **Dataset:** KKBox churn prediction dataset (subscription behavior + transactions + user activity features)
- **Label:** `is_churn` (binary)

---

## Split Strategy

- **Split key:** `txn_last_date` (date of the subscriber's last transaction), stored as a `YYYYMMDD` integer
- **Cutoff policy:** `quantile_0.8`: `13_train_champion_lgbm.py` takes the 80th percentile of `txn_last_date`, which resolves to **2017-02-24**
- **Train:** rows where `txn_last_date <= cutoff`
- **Validation:** rows where `txn_last_date > cutoff` (193,205 rows, 1.24% churn)
- Rows with an unparseable `txn_last_date` are dropped before the split
- **Parsing caveat:** the script calls `pd.to_datetime` without `format="%Y%m%d"`, so integers become nanosecond offsets from 1970 and `metrics.json` stores the cutoff as `1970-01-01 00:00:00.020170224`. Ordering is preserved, so the split is chronological and correct; only the stored label is unreadable. `cloud/sagemaker/train.py` parses correctly but uses a fixed 2017-01-31 cutoff, so its validation set differs.

## Decision Policy

Both cutoffs are in `threshold.json`. The API (`src/serving/api.py`) uses the ROI-optimal threshold for `churn_label` and loads `deployment_policy_v2.json` to return an `action` per score: the incentive above 0.68, a $0.50 nudge down to 0.2058 (the 10,000th rank), monitor below. Tiered, that nets $24,306 per cycle on validation (12% nudge save rate, illustrative). v1 (`deployment_policy.json`, top-K primary) is superseded; see [docs/decisions.md](../../docs/decisions.md) D4–D5.

| Policy | Type | Key Parameter | Simulated net / cycle | Use Case |
|---|---|---|---:|---|
| **Default** | ROI-optimal threshold | t = 0.68 (1,478 contacts, precision 70.6%) | $17,666 | Incentive-based outreach |
| **Capacity** | Top-K | K = 10,000 (≈ t = 0.2058, precision 18.0%) | −$6,776 with the $5 incentive for all | Fixed contact capacity; pays only with a cheap channel below the top 1,478 |

Net value is simulated on the validation window under the assumptions in `reports/business_assumptions.md` ($120 per save, $5 per contact, 20% save rate), not realised revenue.

## Reproducibility Checklist

To keep this "champion" stable:

1. Use the exact same processed dataset version used for the run
2. Score using the exact columns and order in `feature_list.json`
3. Apply the policy from `threshold.json` for binary actioning
4. If retraining is required, retrain deterministically using:
   - `flaml_best_params.json`
   - Fixed random seed
   - Same time split definition (`quantile_0.8` on `txn_last_date`, cutoff 20170224)

## Known Limitations

- **Label delay:** In production, churn labels arrive ~30 days after scoring. During that window, only input drift signals provide early warning
- **Calibration:** Model probabilities are not calibrated — scores are used for ranking (top-K) and threshold comparison, not as true probability estimates
- **Single holdout window:** Validation is one chronological slice (last transaction after 2017-02-24). A rolling-window backtest across multiple months would provide more robust performance estimates
